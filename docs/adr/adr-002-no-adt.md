# ADR-002: FP(ADT) 도입 보류 — 단순 도메인 모델 유지

## 상태

채택 (Accepted) — FP/ADT는 지금 도입하지 않는다.

## 맥락

출고 도메인을 모델링할 때, 출고 결과(성공·재고 부족)와 재고 상태를 FP·ADT(sealed 타입·Result)로 표현할지, 명령형·단순 반환으로 둘지 정해야 한다. 앞서 재고 부족은 *정상 분기*(예외 아님)로 보기로 했다.

## 후보군

### 1. 명령형·단순 반환

재고는 수량 값, 출고 결과는 단순 반환(남은 재고 / 부족).

- **장점:** 단순·익숙. MVP 규모에 맞는다.
- **단점:** 결과 분기를 타입이 강제하지 않는다.

### 2. 경량 ADT (네이티브 Java)

출고 결과를 `sealed` 타입(성공/부족)으로, 재고를 상태 타입으로.

- **장점:** 배타적 결과를 타입으로 표현, 컴파일러가 분기 누락을 잡는다.
- **단점:** 지금 상태 수가 적어 이득이 약하고, 타입 설계가 는다.

### 3. 풀 FP

Either/Result 모나드, Vavr 등 전면 함수형.

- **단점:** MVP에 과하고 라이브러리 의존이 는다.

## 결정

**FP·ADT를 도입하지 않는다.** 재고는 단순 수량 값(불변식: 수량 ≥ 0), 출고 결과는 단순 반환(남은 재고 / 부족)으로 둔다.

## 근거

- ADT의 이득(컴파일러 망라성, 배타적 분기의 타입 안전)은 *서로 배타적인 상태·결과가 풍부할 때* 인과로 닿는다. 지금 재고는 사실상 수량 하나(≥0), 출고 결과는 성공/부족 두 갈래뿐이라 그 조건을 못 채운다.
- 도입하면 이득 없이 비용(타입 설계·보일러플레이트)만 는다. 과제의 MVP 목적과 어긋난다.
- "재고 부족은 정상 분기"라는 모델은 ADT 없이 단순 결과로도 표현된다.

## 재검토 트리거

재고 상태가 풍부해지면(예: 예약·보류·만료 같은 상태가 생기면) ADT를 다시 본다.
