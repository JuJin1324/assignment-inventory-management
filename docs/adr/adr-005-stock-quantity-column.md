# ADR-005: 재고 저장 모델 — 수량 컬럼

## 날짜

2026-06-02

## 상태

채택 (Accepted)

## 맥락

재고를 RDBMS에 어떻게 저장할지 정해야 한다 — 현재 수량을 컬럼 하나로 들지, 입출고 변동을 행으로 쌓아 합산할지.

## 후보군

### 1. 수량 컬럼

`stock` 테이블에 현재 수량 컬럼 하나, 출고 시 `UPDATE`로 차감.

- **장점:** 단순, 현재 재고를 바로 조회. 도메인 `Stock.quantity`와 1:1로 매핑. ADR-004(하나로)와 매끄럽게 맞물림.
- **단점:** 변동 내역(언제 얼마나 출고됐는지)이 남지 않는다 — 감사·추적 불가.

### 2. 변동 이력 합산

입출고 변동을 행으로 쌓고(append-only), 현재 재고는 합산으로 구한다.

- **장점:** 전체 이력 보존(감사·추적), 동시성 충돌에 유리.
- **단점:** 현재 수량마다 집계가 필요해 성능·복잡도가 는다. MVP에 과하다.

## 결정

**수량 컬럼으로 간다.** `stock` 테이블에 현재 수량 컬럼을 두고, 출고 시 `UPDATE`로 차감한다.

## 근거

- 현재 도메인이 `Stock.quantity` 단일 값이라(ADR-002 "단순 수량 값"과 같은 정신) 수량 컬럼과 1:1로 떨어진다.
- 동시성은 별도 에픽으로 미뤘으므로 이력 합산이 주는 동시성·감사 이점은 지금 요구가 아니다.
- MVP 단순성 우선(ADR-004와 같은 방향).

## 재검토 트리거

감사 추적·변동 이력·동시성 충돌 처리가 실제 요구로 들어오면 변동 이력(append-only) 모델을 다시 본다.
