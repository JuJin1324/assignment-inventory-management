# ADR-006: 영속 계층 테스트 — @DataJpaTest 슬라이스 둔다

## 날짜

2026-06-02

## 상태

채택 (Accepted)

## 맥락

영속 어댑터(리포지토리) 테스트를 둘지 정해야 한다. Story 1은 순수 도메인 단위 테스트만 있었다. Story 2에서 도메인에 직접 JPA를 매핑(ADR-004)하고 공통 컬럼·Auditing·`@Version`이 새로 들어온다.

## 후보군

### 1. 둔다

`@DataJpaTest` 슬라이스로 저장 후 조회·매핑을 검증.

- **장점:** 매핑·Auditing·`@Version` 설정이 실제로 맞물리는지 잡아준다. 도메인 직접 매핑 + 공통 컬럼이 이번에 새로 들어와 검증값이 크다.
- **단점:** 테스트용 DB 구성 부담.

### 2. 안 둔다

Story 2 완료 기준의 "저장 후 조회 확인"을 psql·Make 수동 확인으로만.

- **장점:** 가볍게 끝.
- **단점:** 매핑 회귀를 자동으로 못 잡는다. 수동 확인은 휘발된다.

## 결정

**둔다.** `@DataJpaTest` 슬라이스로 저장 후 조회와 매핑을 검증한다.

## 근거

- 도메인 직접 매핑 + Auditing/version 설정이 맞물리는 지점이 많은데, 가벼운 `@DataJpaTest` 슬라이스 하나가 그 회귀를 자동으로 잡는다.
- 수동 확인(psql·Make)은 한 번 보고 휘발되지만, 테스트는 회귀를 지속적으로 막는다.

## 메모

테스트용 DB를 무엇으로 띄울지(Testcontainers로 PostgreSQL 충실 / H2 경량 / 실 DB)는 이 ADR이 아니라 plan-tasks 세부에서 정한다.
